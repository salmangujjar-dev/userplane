# Frame Managers

Frame managers handle the lifecycle of iframes: mounting, bridge connection, session management, and teardown.

## Class Hierarchy

```
IFrameManager (interface)
    │
    └── BaseFrameManager (abstract class)
            │
            ├── RecordingFrameManager
            ├── VerificationFrameManager
            └── CaptureFrameManager
```

## `IFrameManager` Interface

```typescript
interface IFrameManager {
  tryMount(params: RecorderParams): boolean;
  unmount(): void;
  isMounted(): boolean;
  getFrame(): RecorderFrame | null;
  isBridgeConnected(): boolean;
}
```

| Method                | Description                                                 |
| --------------------- | ----------------------------------------------------------- |
| `tryMount(params)`    | Attempt to mount the iframe. Returns `true` if successful.  |
| `unmount()`           | Remove the iframe from the DOM and disconnect the bridge.   |
| `isMounted()`         | Returns `true` if the iframe is currently in the DOM.       |
| `getFrame()`          | Returns `{ overlay, iframe }` or `null`.                    |
| `isBridgeConnected()` | Returns `true` if the PostBridge connection is established. |

## `BaseFrameManager` (Abstract)

Provides the shared lifecycle implementation. Subclasses implement the bridge-specific behavior.

```typescript
abstract class BaseFrameManager implements IFrameManager {
  protected frame: RecorderFrame | null = null;
  protected mounted: boolean = false;

  // Template method — concrete: creates frame, calls establishBridge
  tryMount(params: RecorderParams): boolean { ... }

  // Template method — concrete: disconnects bridge, removes DOM elements
  unmount(): void { ... }

  // Abstract — subclasses provide their specific bridge connection
  protected abstract establishBridge(iframe: HTMLIFrameElement, params: RecorderParams): void;

  // Abstract — subclasses provide their bridge connection type
  protected abstract getBridgeConnection(): BridgeConnection | null;

  // Concrete
  isMounted(): boolean { return this.mounted; }
  getFrame(): RecorderFrame | null { return this.frame; }
  isBridgeConnected(): boolean { return this.getBridgeConnection()?.isConnected() ?? false; }
}
```

The Template Method pattern means `tryMount` and `unmount` always execute the same DOM operations, while subclasses customize bridge behavior.

## `RecordingFrameManager`

The primary frame manager, used for recording sessions.

```typescript
class RecordingFrameManager extends BaseFrameManager implements IRecordingFrameManager {
  // Additional methods beyond IFrameManager:
  getRecordingContext(): RecordingContext | null;
  getSessionId(): string | null;
  getLinkId(): string | null;
}
```

Internally holds a `RecorderBridgeConnection` which:

- Exposes `RecorderHostSchema` to the recorder
- Tracks recording state transitions (`inactive` → `active` → `retained` → `inactive`)
- Manages unload protection (`beforeunload` handler)
- Cleans up URL parameters after session start

**What makes it different:**

- Creates a full-screen overlay + iframe (visible to the user)
- Manages session state machine
- Has the most complex bridge schema (both host and guest)

## `VerificationFrameManager`

Used for domain verification flows.

Internally holds a `VerificationBridgeConnection` which:

- Exposes `VerificationHostSchema` to the verification iframe
- Makes the API call from the parent window context
- Handles close requests from the verification UI

**What makes it different:**

- Also creates a full-screen overlay + iframe
- No session state — verification is a one-shot flow
- Bridge schema is simpler (two methods only)

## `CaptureFrameManager`

Used for the hidden cross-tab coordination iframe.

```typescript
class CaptureFrameManager extends BaseFrameManager implements ICaptureFrameManager {
  // Additional methods:
  extractMetadata(): Promise<TabMetadata | null>;
  updateRecorderState(state: CaptureRecorderState): Promise<void>;
  ping(): Promise<boolean>;
}
```

Internally holds a `CaptureBridgeConnection` which:

- Manages the hidden 1×1 iframe
- Coordinates blur state via `BlurManager`
- Exposes metadata extraction to the recorder
- Tracks recording state updates from the main recording session

**What makes it different:**

- Creates a hidden 1×1 pixel iframe (no overlay, no visible UI)
- Stays mounted for the entire page lifetime (not just during recording)
- Has both capture-specific host and guest schemas

## `FrameManagerFactory`

Creates the appropriate manager for a given action type:

```typescript
class FrameManagerFactory {
  create(action: ActionType): IFrameManager {
    switch (action) {
      case 'recording':
        return this.createRecordingManager();
      case 'verify':
        return this.createVerificationManager();
      case 'capture':
        return this.createCaptureManager();
    }
  }
}
```

The factory is configured once with workspace IDs, tab reference, and options. Each call to `create()` produces a new, independent manager instance.

## Frame Config

Each manager builds its iframe configuration using `FrameConfigBuilder`:

```typescript
// Recording/Verification: full-screen with overlay
const config = new FrameConfigBuilder()
  .withUrl(recorderUrl)
  .withZIndex('2147483647')
  .withOverlayBackground('rgba(0, 0, 0, 0.5)')
  .withBackdropBlur(true)
  .withSandbox('allow-same-origin allow-scripts allow-popups')
  .withAllow('microphone; camera; display-capture; screen-wake-lock')
  .withAllowFullscreen(true)
  .build();

// Capture: hidden, no overlay
const captureConfig = new FrameConfigBuilder()
  .withUrl(captureUrl)
  .withZIndex('-1') // doesn't matter — it's hidden
  .build(); // overlay not created for capture
```
