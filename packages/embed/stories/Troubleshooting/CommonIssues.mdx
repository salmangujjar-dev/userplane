# Common Issues

Quick reference for diagnosing and fixing the most common problems with `@userplane/embed`.

## Symptom → Cause → Fix

| Symptom                                | Likely Cause                                        | Fix                                                                             |
| -------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------- |
| `window.userplane` is `undefined`      | Manifest fetch failed or main bundle not yet loaded | Check Network tab for failed requests; see below                                |
| Recorder never opens on recording link | Missing `<meta>` workspace tag                      | Add `<meta name="userplane:workspace" content="ws_...">`                        |
| CSP error blocking script injection    | `script-src` policy missing nonce or CDN domain     | Add CDN domain to `script-src`; or pass `nonce` attribute                       |
| Old version still loading after deploy | Manifest still cached (5-min TTL)                   | Wait 5 minutes, or hard-refresh (`Ctrl+Shift+R`)                                |
| `script.js` returns 404                | Wrong CDN URL in script tag                         | Verify the URL matches your `CDN_DOMAIN` + `R2_CDN_PREFIX`                      |
| Deploy fails with auth error           | Missing or incorrect R2 env vars                    | Run `--dry-run --manifest-only` to test credentials                             |
| Auto-init fires before metadata is set | `initialize()` runs before your code                | Call `initialize({ openImmediately: false })`, set metadata, then call `open()` |

## window.userplane is undefined

**Symptoms:** `window.userplane` is `undefined` in the console.

**Step-by-step diagnosis:**

1. Open DevTools **Network** tab and reload the page
2. Look for `script.js` — did it load with a 200 status?
3. Look for `manifest.json?t=...` — did it load with a 200 status?
4. Look for `main.{hash}.js` — did it load with a 200 status?

If `manifest.json` fails (404, CORS error, or network error), the bootstrap logs:

```
[userplane] Failed to load manifest: 404
```

Check the Console tab for this message.

**Common causes:**

- Wrong CDN URL in `<script>` tag → `script.js` returns 404
- R2 bucket not public or CDN misconfigured → manifest returns 403
- The bundle is still loading (async) → try accessing `window.userplane` after a delay

## Recorder Never Opens

**Symptoms:** Visiting a recording link does nothing. No recorder UI appears.

**Check:**

1. Is `<meta name="userplane:workspace" content="ws_...">` in the `<head>`?
2. Does `window.userplane.isInitialized()` return `true`?
3. What does `window.userplane.getRecordingState()` return?

**Missing meta tag:**

```html
<!-- Add this to <head> -->
<meta name="userplane:workspace" content="ws_your_workspace_id" />
```

**Expired token:** Recording tokens are short-lived. If the link is more than a few minutes old, the token may have expired. Generate a new recording link from the dashboard.

## CSP Errors Blocking Script Injection

**Symptoms:** Console shows CSP errors like:

```
Refused to load script 'https://cdn.example.com/embed/main.abc.js'
because it violates the Content Security Policy directive: "script-src 'self'"
```

**Fix:** Add the CDN domain to your CSP:

```
Content-Security-Policy: script-src 'self' https://cdn.example.com;
```

If you use nonces, pass the nonce to the bootstrap tag:

```html
<script src="https://cdn.example.com/embed/script.js" nonce="your-page-nonce" defer></script>
```

The bootstrap will automatically pass the nonce to the injected `main.{hash}.js` script tag. Both scripts need the same nonce.

## Old Version After Deploy

**Symptoms:** Users are still running the old recorder version after a new deploy.

**Why this happens:** The manifest has a 5-minute HTTP cache (`max-age=300`). Users who loaded the manifest recently won't fetch the new one until their cache expires.

**Fix options:**

- **Wait:** Up to 5 minutes, all users will see the new version
- **Hard refresh:** `Ctrl+Shift+R` (Windows/Linux) or `Cmd+Shift+R` (Mac) clears the browser cache
- **Reduce TTL:** Change the manifest `Cache-Control` to a shorter TTL (e.g., `max-age=60`) at the cost of more CDN origin requests

## Deploy Fails with Auth Error

**Symptoms:** `bun run deploy:cdn` fails with:

```
AccessDenied: Access denied
```

or similar R2/S3 errors.

**Diagnosis:**

```bash
# Test credentials without uploading
bun run upload:cdn --env=production --dry-run --verbose

# Test with only the manifest (lowest risk operation)
bun run upload:cdn --env=production --manifest-only --dry-run
```

**Check:**

1. Are all 6 env vars set in `.env.production`? (see **[Environment Setup](../?path=/docs/deployment-environment-setup--docs)**)
2. Is `R2_CDN_ACCOUNT_ID` correct? (found in Cloudflare dashboard)
3. Does the R2 API token have **Object Read & Write** permissions on the bucket?
4. Is `R2_CDN_BUCKET_NAME` spelled correctly?

## Auto-init Fires Before Custom Metadata Is Set

**Symptoms:** Recordings don't have the expected metadata attached because your metadata-setting code runs after `initialize()`.

**Root cause:** The embed script initializes asynchronously when `main.{hash}.js` loads. This may happen before or after your synchronous scripts run, depending on timing.

**Fix:** Disable `openImmediately`, set metadata, then open:

```javascript
window.addEventListener('load', () => {
  // Re-initialize with openImmediately: false
  window.userplane.initialize({ openImmediately: false });

  // Now set metadata synchronously
  window.userplane.set('userId', getCurrentUserId());
  window.userplane.set('plan', getUserPlan());

  // Manually open the recorder (checks URL params again)
  window.userplane.open();
});
```

Alternatively, use a `MutationObserver` or polling pattern to detect when `window.userplane` is available, then set metadata immediately.
