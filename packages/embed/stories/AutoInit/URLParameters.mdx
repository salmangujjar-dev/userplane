# URL Parameters

The embed package automatically detects recording links in the URL and opens the recorder without any additional code.

## How URL Detection Works

During auto-initialization, the SDK inspects `window.location.search` for two parameters:

| Parameter          | Purpose                                     |
| ------------------ | ------------------------------------------- |
| `userplane-action` | The action to take (`open` = open recorder) |
| `userplane-token`  | The recording session token                 |

Example recording URL:

```
https://yoursite.com/dashboard?userplane-action=open&userplane-token=tok_abc123xyz
```

When both parameters are present and `userplane-action=open`, the SDK opens the recorder and associates the session with the provided token.

## URL Cleanup

After consuming the parameters, the SDK removes them from the browser's address bar using `history.replaceState`:

```javascript
// Before: https://yoursite.com/dashboard?userplane-action=open&userplane-token=tok_abc
// After:  https://yoursite.com/dashboard
```

This is clean behavior — users see a normal URL after the recorder opens, and the token is not left in browser history or shared if the user copies the URL.

## Customising URL Parsing

The embed auto-init uses the SDK's default URL parsing. If you need custom behavior — for example, if your app uses a different URL format or the parameters are in a different location — you can override the parsers by calling `initialize()` again after the embed loads:

```javascript
window.addEventListener('load', () => {
  // Override URL parsing after auto-init
  window.userplane.initialize({
    parseUserplaneData: (url) => {
      // Custom URL parsing logic
      const params = new URLSearchParams(url.search);
      return {
        action: params.get('up-action'),
        token: params.get('up-token'),
      };
    },
    applyUserplaneData: (data) => {
      // Custom data application logic
      if (data.action === 'open' && data.token) {
        window.userplane.open(data.token);
      }
    },
  });
});
```

## Timing Consideration

URL detection happens during `initialize()`, which runs when `main.{hash}.js` executes. This is asynchronous relative to page load:

```
Page loads
    │
    ├── Your scripts execute (synchronous)
    │
    └── defer scripts execute
            │
            └── script.js (bootstrap)
                    │
                    └── [async] fetch manifest
                            │
                            └── inject main.{hash}.js
                                    │
                                    └── initialize() ← URL detected here
```

If your app reads URL parameters before this point, the `userplane-action` and `userplane-token` parameters will still be in `window.location.search` at that time — the SDK has not yet consumed them.

## Recording Link Pattern

Recording links are generated by the Userplane dashboard. The typical pattern is:

```
https://yoursite.com/{path}?userplane-action=open&userplane-token={token}
```

Where:

- `{path}` — any path on your site (the recorder opens on top of whatever page is loaded)
- `{token}` — a short-lived token identifying the recording session

The token is single-use and expires. Visiting the link after the token expires will result in the recorder failing to connect.

## Multiple Parameters

The URL may contain other query parameters that the SDK ignores:

```
https://yoursite.com/dashboard?utm_source=email&userplane-action=open&userplane-token=tok_abc&ref=newsletter
```

Only `userplane-action` and `userplane-token` are consumed. All others remain in the URL.
